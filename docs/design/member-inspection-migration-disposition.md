# Member inspection migration disposition

This document records the implementation and evidence disposition required by
issue
[#4649](https://github.com/richlander/dotnet-inspect/issues/4649) before the
member-inspection migration begins. The owning architecture remains
[Member inspection planning and Metadata projection](member-inspection-planning-and-metadata-projection.md).
This document assigns historical work to that architecture; it does not create
a second owner or authorize any behavior change.

The matrix separates implementation from evidence deliberately. A branch can
use an architecture that must be replaced while still carrying the best
compiler-produced fixture, hostile close negative, or user-visible regression
for the replacement. Frozen branches remain historical and reproduction
evidence. They are not merge candidates and must not be repaired, rebased, or
restacked to implement this plan.

## Slice entry conditions

This disposition changes no product behavior. It unlocks only the next
characterization step:

1. Slice 1 builds one matrix over every route named by the owning design and
   uses the retained fixtures above to compare full, summary, and focused
   projections.
2. Slice 2 may begin only after that matrix is complete. It consumes retained
   routing behavior but introduces immutable parsed and resolved plans rather
   than carrying forward transitional option flags.
3. Slice 4 is the first point at which API section lenses bind to a typed query
   domain. It must consume the shared compiled inspection-domain seam proven by
   Diff and Package Profile; it must not introduce an API-specific executor.
4. Slices 5-7 re-derive Metadata and CSharp behavior from the retained evidence
   under their owning focused designs. An old green test result does not
   authorize its old implementation.
5. Slice 8 deletes every retained compatibility carrier identified above after
   no production path depends on it.

Any later discovery of coherent work on these frozen heads must be added here
before that work is reused. Mechanical fix commits do not need separate rows
when they only repair one claim already represented by the matrix.
