# Example explanation documents

These checked-in JSON examples are pretty-printed so the data model can be
read directly. They are proposed shapes derived from actual product data,
not JSON emitted by an implemented selection. The byte comparisons in the
parent documents use minified JSON; these files intentionally use indentation.

| Example | What to inspect |
| --- | --- |
| [style-sparse.json](style-sparse.json) | Preferred candidate: shared records plus complete positive property sets and conflict-group membership; no repeated false/null flags. |
| [style-shared.json](style-shared.json) | Record-based baseline: 17 discoverable choices with direct properties and four shared tier records keyed by ID. |
| [style-flat.json](style-flat.json) | Same core data with tier detail repeated inside each choice. |
| [style-indexed.json](style-indexed.json) | Same core data with keyed choices, explicit order, and derived tier/conflict indexes. |
| [package-query-facets.json](package-query-facets.json) | All 19 facets, 14 CLI-exposed term IDs, and locally resolvable required context. |

Start with `choices[0]`, `choice_sets`, and `conflict_groups` in the sparse
file, then compare `choices[0]` and `tiers.Synthesis` in the shared style file.
Then compare the repeated tier object in the flat file and `tier_choices` in
the indexed file. In the facet file, compare `facets.library-literal`,
`facets.library-target`, and `binding.exposed_facets`: a required contextual
facet is not an independently exposed query term.

## Query the examples

From the worktree root:

```bash
jq .choice_sets.corpus_endorsed \
  tools/ExplainReadingScenarios/examples/style-sparse.json
jq '.conflict_groups["var-spelling-style"]' \
  tools/ExplainReadingScenarios/examples/style-sparse.json
```

```bash
jq --arg task grouped-menu --arg tier Synthesis --arg id slot-local-names \
  -f tools/ExplainReadingScenarios/shapes/shared.jq \
  tools/ExplainReadingScenarios/examples/style-shared.json
jq --arg task context --arg key library-literal \
  -f tools/ExplainReadingScenarios/facets/explore.jq \
  tools/ExplainReadingScenarios/examples/package-query-facets.json
```

The [style comparison](../shapes/README.md) explains the normalization choices.
The [worked agent demo](../facets/README.md) supplies the exploration steps and
identifies missing operand constraints and CLI-context authoring metadata.
These examples do not pretend those missing facts are already exposed.

## Provenance and regeneration

The sparse example removes repeated flag fields; absence from its complete sets
means false only for a known selected record. Unavailable observations are not
encoded as negative membership.

Style examples were generated by `compare-shapes.py` from the actual browser
vocabulary export, captured by `CaptureBrowser.csproj`. The facet example was
generated by `facet-demo.py` using CLI `0.27.0+5ce2e00`. They contain the same
JSON values as those measured experiments; pretty-printing changes formatting
only. Completeness is scoped to the selected populations, rather than claiming
complete contract or arbitrary graph coverage.

Run the parent scripts into a temporary output directory using their documented
commands, then pretty-print the resulting `flat.json`, `shared.json`,
`indexed.json`, `sparse.json`, and `facet-document.json` into the corresponding example files.
Keep owner data and derived indexes together when refreshing examples. These
files are design specimens, not independently authored production inventories.
