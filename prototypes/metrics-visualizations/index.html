dotnet-inspect · visual exploration

Make the library legible before explaining the metric.

Three D3.js sketches using real compiled method-body evidence. Each one starts with a question a developer can answer without knowing what cyclomatic complexity or P95 means.

Real data · ILInspector.Analysis (13,100 bodies) and ILInspector.Research (4,008 bodies)

01 · orient

Where is the implementation?

Start with familiar territory: a map of the library. Large regions contain more implementation, while warmer color means more branching density relative to the selected library. Click a region to zoom in.

02 · follow

Where does the code flow?

Relationships make “spaghetti code” visible. The same real call evidence can be lowered three ways: a flow from source to destination, an arc that exposes crossings, or a chord that shows mutual pull.

03 · compose

What kind of code fills the library?

Composition is easier to read as a shape than as a list of percentages. The radial view shows namespace and type hierarchy; the donut turns implementation size into a few plain-language bands.

Radial map · namespace → type click a segment to zoom

04 · compare

What changed between libraries?

A diverging chart gives direction a visual meaning. The center is the shared baseline; bars to the left or right show which namespace or metric carries more implementation volume in one assembly or the other.
