# Explicit cfg -> module overrides for eng/run-tla-checks.sh.
#
# The script pairs a .cfg with the sole .tla module in its directory, or with
# a same-named module when a directory has more than one. That heuristic is
# wrong wherever a .cfg is meant to run against a model-checking harness
# module (commonly named `<Model>_MC.tla`) instead of the base spec, because
# TLC's .cfg grammar cannot express some constant values directly (see the
# comment atop the harness module itself). List every such directory's cfg
# files here rather than letting the heuristic silently pick the wrong
# module; the script fails if a cfg matches neither this file nor the
# heuristic.
#
# Format: one `<path-to-cfg>=<module-name>` pair per line. <module-name> is
# the .tla module base name (no extension) and must exist beside the cfg.
